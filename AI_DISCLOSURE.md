# AI Use Disclosure – CirKit (Team Yukthi, AX26-611)

| Tool | Used for | Where |
|------|----------|-------|
| Claude (Anthropic) | AI coding assistant: architecture planning, starter code for agents, API and frontend (Pillars 1 and 2, dashboard) | backend/, docs/ |
| Llama 3.3 70B via Groq API | Runtime reasoning: Pillar 1 Forecaster and Critic agents; Pillar 2 Router agent (suggests use first / chef's special / staff meal / donate); Pillar 3 Matcher (picks an NGO from tool results) and Outreach (writes the pickup message) | backend/agents/common.py, graph.py, expiry_graph.py, rescue_graph.py |

What the AI does NOT do: in Pillar 2 the LLM never decides whether food is safe. Safety
(expired, too close to expiry, opened high-risk food) is decided by plain rules in
backend/core/food_safety.py, and a rule-based safety critic re-checks every LLM suggestion.
In Pillar 3 the same holds: whether cooked food is safe for people is decided only by rules in
backend/core/leftover_safety.py, and a rule-based critic re-checks every match. The chat's
"still available?" bot answers from live data, not the LLM. All NGOs and recycle partners are mock.
In Pillar 4 (Revenue & Impact) the LLM only adds an audit note, recommends upgrades, picks vendors and writes the
ESG summary. Which records count, points, tiers, the critic's budget/payback rules and all invoice maths are plain
rules in backend/core/impact.py and backend/core/ledger.py. Green Credit Points are loyalty points, not carbon
credits; all vendors, prices and CO2 figures are mock estimates, and no real payment is processed.
Every LLM call has a rule-based fallback, so the app works without internet.

Synthetic data: backend/data/ was generated by generate_data.py for the demo.
Shelf-life values in backend/data/shelf_life.json are documented, FSSAI-guided demo assumptions,
not FSSAI-certified values.
